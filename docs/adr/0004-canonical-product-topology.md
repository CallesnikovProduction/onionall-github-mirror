# ADR 0004 — Canonical product topology and evidence boundaries

Status: selected by the owner M5 specification, integration qualification OPEN.
Date: 2026-11-04. No topology retirement or production wiring change in this ADR.

## Decision and invariants

`CrawlExecution.start()` generates resources and invokes
`CrawlExecution.topology(Path)`, delegating to pure `CrawlTopology.build(Path)`,
as the single product topology builder. Do not
merge historical capabilities into that chain. Frontier remains the only owner
of admission, reservations, quota, scheduling, leases and retry due dates; H2
records observations. S1-01 capability clients/server must remain paired.

Current product path: CapabilitySpout -> URLPartitionerBolt -> SimpleFetcherBolt
-> JSoupParserBolt -> StdOutIndexer. Fetch/parse/index status streams go to
CapabilityArchiveStatusUpdaterBolt, grouped by URL. The product has five bolts
and seven streams; resource includes load defaults then the generated config.

| Boundary | Product generated by CrawlExecution | Root crawler.flux / historical baseline |
| --- | --- | --- |
| Spout | CapabilitySpout, mandatory existing token | Stock URLFrontier Spout |
| Partition | URLPartitionerBolt, FIELDS(key) to fetcher | Same partition contract |
| Fetch | SimpleFetcherBolt | FetcherBolt |
| Parse | JSoupParserBolt | SiteMapParserBolt -> FeedParserBolt -> JSoupParserBolt -> RedirectionBolt; Tika branch |
| Index | StdOutIndexer, no persistent search index | StdOutIndexer, via direct shunt or Tika |
| Status | CapabilityArchiveStatusUpdaterBolt, three status sources | Stock StatusUpdaterBolt, six status sources |
| Size | Five bolts, seven streams | Nine bolts, fifteen streams |
| Discovery/archive | DurableDiscoveryFilter then ArchiveParseFilter, generated resources | Defaults/fixture-specific overrides; not implicit durable admission |
| Transport | Generated HTTP/HTTPS TorProtocol, tor.mode ONLY, approved origin allowlist | Root defaults not a product Tor boundary; M2/M3 replace transport in derived fixtures |
| Scheduler | Versioned owning admission Frontier, sync-WAL quota/reserve/enqueue | Stock/fixture Frontier contract; cannot inherit product authority |

Feed, sitemap and Tika processing are not current product features. Root Flux
stays available for its historical baselines; no scripts are retired here.
Changing M0/M1 stock clients to tokenless clients against a protected server is
not a valid acceptance substitution.

## Concrete source and ordering

`src/main/java/dev/onionall/brawler/admission/CrawlExecution.java`:
`start()` writes config, ordered parse filters and topology.json, publishes the
job resources into a unique runtime JAR and starts the worker. `configuration()`
sets both protocol implementations, ONLY mode, scope, robots, no redirects,
HTML/content limits and no transferred credentials. `topology()` delegates the
unchanged graph to pure CrawlTopology; it never selects the historical Flux.

`ArchiveParseFilter` commits archive data before parser emission;
`CapabilityArchiveStatusUpdaterBolt.store()` calls the shared
`ArchiveStatusUpdaterBolt.recordOutcome()` before authenticated Frontier storage.
The copied capability adapters retain upstream scheduler/ACK/reconnect behavior.
No second status scheduler, H2 pending queue or DIRECT fallback is introduced.

## Product fixture and open gate

bundle, owning Frontier JAR and verified lifecycle-patched Storm image exist.

No capability/transport policy changes or forced direct routing to make it pass.

## Read-model decision required before lifecycle implementation

Current RocksDB terminal updates delete the scheduling row and leave an empty
existence pointer. Recovery reconstructs "completed" as UNSCHEDULED; it cannot
tell successful fetch from terminal failure. `getURLStatus()` reconstructs URL
identity for those rows without the discarded scheduling metadata. H2 failure
records are observations, not an authoritative scheduler terminal ledger.

The ARCH specification stop condition applies: "scheduler states cannot be
inferred reliably". Do not implement DONE/FAILED or COMPLETE by subtracting
archived pages or treating UNSCHEDULED as successful. Proposed bounded contract:
expose UNSCHEDULED and null/UNKNOWN success/terminal counts; reserve COMPLETE for
independently proved outcomes. Alternative: separately reviewed durable terminal
provenance design with compatibility/rollback gates. No new persistent state is
introduced before this decision. ARCH read-model/DOM/retry dependent scope is OPEN.

Rollback of this ADR is documentation-only; historical tests/capabilities and
all product scheduling/transport behavior remain intact.

### Owner resolution — 2026-11-04

The owner selected UNKNOWN/null success/terminal, with COMPLETE permitted only
for an independently proved result. ARCH read-model work may proceed under that
contract; the earlier decision hold is resolved. No durable terminal-provenance
schema is introduced. STATE_LIST/STATE_COUNTS in the existing authenticated Command
provide bounded observations; see the current frontier-server README. Future due
is SCHEDULED_WAIT, not automatically a retry. UNSCHEDULED remains unresolved
completion. Product graph E2E gates above remain open independently of this decision.

PASS at208a07e (plan/admit/archive/503/retry/restart/quota replay). This supersedes

## Archive-fault contract: owner decision, separate design approval pending

Actual ParserArchiveAckCharacterizationTest calls installed JSoupParserBolt.prepare
and execute with real ArchiveParseFilter/H2 and a corrupted immutable blob fixture.
Success commits before default emission/ACK. Fault produces exactly ERROR/status
then ACK, no fail, no FETCHED/default output and zero snapshots/pages. Installed
handleException implements that path. This confirms the component behavior, not a
full Storm ACK tree after durable child reservation. Existing positive archive
callback tests did not establish parent-fail behavior. Characterization PASS is
NOT the requested acceptance; verify explicitly retains archive-write-ack NOT RUN.

Owner selected parent tuple FAIL plus bounded retry through existing Storm/Frontier,
and requested a SEPARATE minimal design review before implementation. Proposed:

1. Keep installed JSoup parser logic. Add a narrowly scoped parser adapter and a
   trusted transient archive-commit-failure marker. Clear it per execute; only the
   actual archive exception sets it. No generic parser/admission/robots behavior
   change. Never emit a fetched/default document on archive fault.
2. For this fault only, transform the parser ERROR/status intent into FETCH_ERROR
   tagged error.source=archive, then fail the original tuple exactly once instead
   of ACK. Do not emit the old terminal ERROR alongside it. Capability status
   updater remains the sole scheduling writer, with observation-before-write.
3. Reuse current DefaultScheduler, default120min backoff and max.fetch.errors=3
   (shared existing URL processing failure budget, no new counter/schema/scheduler).
   Keep failure phase ARCHIVE ahead of generic FETCH classification. Do not claim
   a separate distinct network-attempt count or a terminal Frontier outcome.
4. Spout.fail is NOT a durable retry/backoff operation: installed AbstractQueryingSpout
   only removes beingProcessed and increments a metric. Retry eligibility must come
   from the existing authenticated status write/Frontier due time, or its held lease
   if that write cannot commit. Never add immediate local replay/blanket retry.
5. If archive observation cannot commit (e.g. H2 unavailable), preserve existing
   prohibition on Frontier status write. Fail tuple, leave current lease/reservation,
   bound the worker by its existing TTL and require manual storage repair/resume.
   A global durable retry count cannot be proved while both observation/status
   persistence are unavailable: report UNKNOWN, no fake exhausted/complete result.

Compatibility: new parser adapter in canonical graph only; token-bearing clients
and owning Frontier stay paired. Existing protobuf/RPC/schema/quotas/Tor unchanged.
Transient marker is not new persistent scheduling state. Semantic change is from
immediate terminal parser ERROR to the shared bounded error policy for archive
faults only. Rollback after proved worker stop restores the old adapter/class and
ERROR+ACK behavior, preserves all data and markers; no volume reset/schema downgrade.

Approval gates for implementation: real parser success still ACK1/fail0 after
commit; archive fault emits one archive FETCH_ERROR, fail1/ACK0/default0; actual
status callback records history before authenticated write; 1/2 errors keep the
same120min next due, third reaches existing terminal policy; audit-write failure
makes no Frontier write; real generated Storm fixture proves child reservation
survives parent archive fault with zero phantom snapshots, no extra quota, no
before-due fetch and successful after-due repair/replay. Existing non-archive
parser, robots, discovery, auth/reconnect, recovery and Tor tests stay unchanged.
This design is NOT implemented or accepted by the characterization test.
