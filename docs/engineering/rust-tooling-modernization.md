# Модернизация инструментов Onionall Brawler

## Вычислительное ядро архива и Research

### Аудит целостности, 25 ноября 2026

В аудите использованы рабочее дерево первого переноса и JVM-оракул, заново
собранный из `git archive 31ce1d7`. В CommonMark подтверждены два способа
потерять code-ограждение: двойной CR в inline code и многострочный `pre`
в элементе списка с длинным номером. При стыке inline-ограждений буквальная
закрывающая скобка из кода могла подменить назначение окружающей ссылки.
Синтаксически опасный код в inline контексте теперь выводится экранированным
текстом. Самостоятельные ограждённые блоки сохраняют код. Во фрагментах
таблиц, списков, заголовков и цитат экранирование опасного вложенного блока
сохраняет его границы со смежным текстом.

Разметка таблиц ограничивается фактическим бюджетом результата. Предыдущие
дополнительные отсечки 256 столбцов и 4 096 строк теряли валидную структуру
даже на малом выходе. Перед развёртыванием вычисляется нижняя граница
размера прямоугольной таблицы. Крайний whitespace видимого представления
обрезается без расхода бюджета содержимого. Лимит HTML в 128 КиБ и
ограничение глубины Markdown до 128 существовали в JVM.
Предел кадра 2 МиБ относится к ABI. При превышении размера запроса или ответа
многокорневой пакет делится, сохраняя результаты и порядок отдельных корней.
Подтверждённый пример содержал 34 поста с валидными таблицами, но общий
ответ превышал 2 МиБ. Прежний вызов завершался отказом, новый вернул все посты.
У каждого представления остаётся отдельный предел 131 072 UTF-16 единицы.

ABI экспортирует один символ `onionall_content_render_v1`. Указатели,
`i32` длины и ёмкости, little-endian заголовки OCM1/OCT1. Два unsafe блока
production адаптера строят входной read-only slice и копируют полностью
инициализированный результат. Проверки адресных интервалов отвергают
перекрытие и переполнение, а живые размещения и исключительное владение
во время вызова гарантирует вызывающая сторона. Каждый запрос синхронно
выполняется со своей confined arena, которая закрывается на отказе и успехе.
Один synchronized lazy binding загружается из явного абсолютного пути.
Неуспешный поиск символа закрывает arena библиотеки, отказ кэшируется.
Штатная установка использует путь из манифеста рядом с JAR. Это локальная
граница доверия, а ABI-проверка проверяет совместимость. ELF содержит только
платформенные зависимости glibc, libgcc и loader, PE — библиотеки Windows.
`panic = "unwind"` явен для release, unwind перехватывается у ABI.
Фатальная native-ошибка завершает процесс JVM.

Дифференциальный набор включает 622 случая. Включены некорректные байты,
кодировка Windows-1251, скрытые поля, таблицы, переносы строк, ссылки,
оформленные посты и границы глубины. Результаты сравнивались целиком,
включая идентификаторы, текст, цитаты, вложения и флаги. Различия в Markdown
связаны с экранированием кода и одним известным пограничным случаем глубины
вложенной таблицы, где обе стороны отмечают усечение. Для обычного
архивного кода и обоих воспроизведений CommonMark зафиксирован результат
действительного разбора Markdown. Диагностические пробы и исходные логи
сохранены в игнорируемом `.runtime/native-integrity/`.

Graphify AST-граф обновлён по прежнему production scope с добавлением
Kotlin-адаптера и Rust-файлов. `graph.json` содержит 1 702 узла и 4 274 ребра.
Для двух Kotlin файлов AST остаётся частичным. Пользовательская HTML-проекция,
которую строит `build_map.py` из исторического `scope.json`, относится
к предыдущему снимку графа.

### Первый проход миграции

Базовый исходный код — `31ce1d7`. `ArchiveForumExtractor` использует разобранный
Jsoup DOM и найденные `ForumExtractor` границы постов, затем одним вызовом
`NativeContent.renderAll` получает Markdown страницы и постов. Предыдущий
`ArchiveHtmlMarkdown.kt` удалён. `research results` и `research export`
вызывают Rust через `ForumExtractor` для нормализации одного пакета текста
страницы, постов, цитат и авторов. Границы HTML, charset recovery, URL policy
и provenance остаются в существующем JVM-контуре. Для pagination сохранён
исторический forced UTF-8 при несовпадении с найденной кодировкой.

Для обычного UTF-8 снимка чтение исходного кода даёт следующие числа. Они
исключают list/status-запросы, открытие каталога и CAS сохранения результатов.

| Путь | Разборы DOM | Чтения blob | SQL чтения детализации |
| --- | ---: | ---: | ---: |
| Research results | 3 → 1 | 3 → 2 | 3 → 3 |
| Research export | 4 → 1 | 5 → 2 | 6 → 3 |
| Archive researchDocument | 2 → 1 | 3 → 1 | 3 → 3 |

Research удерживает один DOM на итерацию, проверяет job/page/snapshot/hash
и переиспользует те же данные для экспорта. JVM-индекс
`(source_page_id, canonical_target)` сохраняет порядок и неоднозначность
связей файлов с постами. BlobStore сохранил digest и NOFOLLOW-проверки
с ограниченным чтением. Публикация объектов, Frontier и H2 ownership
сохраняют свои контракты.

Протоколы OCM1/OCT1 используют FFM Java 25 и C ABI v1. JVM владеет двумя
раздельными буферами confined arena. Rust освобождает свои временные буферы
до возврата. Unsafe ограничен преобразованием входного указателя и записью
ответа в ABI-адаптере. Ядро запрещает unsafe. Бюджеты включают кадр до 2 MiB,
HTML до 128 KiB, глубину Markdown до 128, таблицу до 4 096 строк и 256 колонок,
максимум 131 072 единиц UTF-16 Markdown на представление. При переполнении
выдаётся ограниченный экранированный текст с признаком усечения. Скрытые
узлы исключаются и внутри таблиц/фрагментов кода. Утрата полной пары
surrogate или синтаксиса escape на границе предотвращается.
Нет отдельных процессов или сетевой изоляции. Unwind перехватывается на ABI,
а фатальная авария или OOM native-процесса остаётся аварией JVM.

14 исходных проб (HTML, Unicode, malformed byte, charset, base, список,
таблица и глубина) дали одинаковые SHA-256 Markdown и статусы в контрольном
сравнении. Новые JVM regressions покрывают лимиты и исключение hidden code.
На Windows JDK 26 x64, release Rust, после прогрева полный
`ArchiveForumExtractor` на списке из 5 000 строк занимал примерно
209 / 13,4 / 4,4 мс для исходного, алгоритмически исправленного JVM и Rust
варианта соответственно. Для неравномерной таблицы — 8,4 / 5,1 / 1,3 мс.
Последние значения включают упаковку, FFM и построение результата.
Замеры проводились на синтетическом корпусе, без Tor и Frontier RPC.
Исходные замеры, временный JVM baseline и воспроизводящие пробы сохранены
в игнорируемом каталоге `.runtime/native-content/`.

Linux JDK 25, синтетические snapshots в локальном H2, медианы пяти замеров
после первого вызова за процесс, мс.

| Команда | 5 страниц, до → после | 100 страниц, до → после |
| --- | ---: | ---: |
| Research results | 379 → 301 | 1 140 → 1 149 |
| Research export | 482 → 276 | 1 869 → 1 104 |

На 100 страницах главный JVM-поток выделял около 965 → 551 MB на экспорт.
Вариативность времени была высокой: один холодный запуск нового экспорта
занял 42,9 с при параллельной сборке. Повтор холодного экспорта 100 страниц
в отдельных процессах занял 6,64–7,24 с на baseline и 3,54 с в обоих
запусках итогового CLI. В отдельной пробе FFM и нормализация
одной короткой строки в заранее выделенных буферах заняли 0,13–0,24 мкс.
После прогрева и принудительного GC общепроцессный RSS стабилизировался на
207 MiB в серии 220 000 пакетных вызовов. Это замер одного синтетического
сценария. Lockfile ядра содержит только локальный crate, внешних Rust
зависимостей для RustSec нет.

Проверка поставки: Docker `content-test` прошёл Rust formatting, Clippy
и 5 тестов, включая 30 000 детерминированных мутаций кадра. Root и crawler
Maven verify в JDK 25 выполнили по 418 тестов, 1 пропущен. Повторная проверка
итоговой библиотеки и CLI — 66 релевантных JVM тестов, 17 тестов поставки
и 43 проверки shell-контрактов. Docker и CI используют один prebuilt-профиль
Maven. SHA-256 экспортированной CI библиотеки совпал с поставляемой.
Все семь Frontier conformance drivers прошли в контейнере JDK 25.
Linux CLI из `target/onionall` выполнил `research results` и `research export`
с 5 и 100 синтетическими snapshots на отключённой сети. На Windows DLL
загрузилась через FFM. CLI вернул диагностический отказ при отсутствии
библиотеки и тестовых несовместимой версии, битом ответе и статусе native
ошибки. Отдельный запуск Rust unit exe на хосте Windows ограничен GNU linker
и кириллическим путём Rustup. Отсутствовавший перевод строки в пустой
секции файлов исправлен по существующему golden test.

Graphify использовался для навигации. Опубликованный граф относится к
`b3650f7`, а его custom projection использует абсолютные пути Linux из
`scope.json`. Для актуализации нужны новая extraction и настройка этого
projection для текущего checkout и native-модуля.

## Реализация, CI и границы безопасности

[Манифест tooling](../../scripts/tooling/Cargo.toml) и
[`Cargo.lock`](../../scripts/tooling/Cargo.lock) собираются в
[существующем Dockerfile](../../docker/toolchain/Dockerfile) с Rust 1.93.0
из закреплённого образа. [`onionall`](../../onionall) направляет канонические
`up`, `status`, `down`, `cli` в [`runtime.rs`](../../scripts/tooling/src/runtime.rs)
и офлайн-проверку кандидата в [`candidate.rs`](../../scripts/tooling/src/candidate.rs).
Обе команды используют [`process.rs`](../../scripts/tooling/src/process.rs)
для ограниченного ожидания и reaping собственных дочерних процессов.
[CI](../../.github/workflows/verify.yml) получает проверенный бинарник из
Docker. Maven/Compose сохраняют свои интерфейсы.

Удалены Python-реализации `scripts/runners/runtime.py` и
`scripts/security/verify_tor_candidate.py`. Изменены launcher, Dockerfile,
build runner, workflow, M2 runner и preflight, их тесты и эксплуатационные
инструкции. Регрессии CLI проверяются в
[`check_runtime_cli.py`](../../test/scripts/check_runtime_cli.py) и
[`test_tor_candidate.py`](../../test/security/test_tor_candidate.py).

- Офлайн-контейнер использует `--network none`, read-only root, сброшенные
  capabilities и запуск без Docker socket. Bundle и шаблон Dockerfile
  смонтированы read-only. GnuPG использует отдельный временный home с
  закреплённым первичным ключом. Для индекса и пакета сверяются размеры и
  SHA-256. Дополнительно проверяются сроки, кодовое имя, версия,
  архитектура и ожидаемый путь.
- Снимки ограничены по размеру. Symlink-назначения и дубли полей
  отклоняются. Публикация резервирует каталог эксклюзивно и пишет
  Dockerfile последним. После ошибки записи возможен неполный каталог без
  Dockerfile. Проверка предполагает отсутствие процесса с теми же
  правами, способного подменять родительские каталоги во время записи.
- Канонический runtime использует существующий socket управляющего
  контейнера. Рабочие контейнеры его не получают. Labels и валидный ID
  обязательны для остановки crawler. Reaping Docker CLI при прерывании
  не доказывает завершение работы на стороне daemon.
- Preflight передаёт hostname с ATYP 3 через SOCKS на буквальном loopback,
  проверяет TLS-имя доверенным CA и читает bootstrap по локальному
  cookie-authenticated control. Регрессия подтверждает строгий verdict
  при неверном доказательстве, а не внешний Tor/HTTPS маршрут.

Справочные контракты [GnuPG gpgv](https://www.gnupg.org/documentation/manuals/gnupg/gpgv.html)
и [Debian control fields](https://www.debian.org/doc/debian-policy/ch-controlfields.html).

## Ограничения и откат

Остаются Python suites, `verify.py`, legacy M1/M2 и контейнерные Tor/fixture
компоненты, тонкие Bash/PowerShell entrypoints, JDK/Maven, Docker Compose и
GnuPG. Одновременные запуски канонических режимов требуют координации
оператора. Проверка наблюдаемого Docker-состояния не сериализует старты.
В задаче не квалифицировались живой Tor и актуальный upstream bundle.

Для отката сначала проверьте остановку управляемой работы и сохраните
состояния, `.runtime`, журналы, тома и ключи. Из исходной ревизии
возвратите согласованный набор из двух Python CLI, маршрутизации launcher,
toolchain/CI и соответствующих тестов. Пересоберите общий toolchain тем же
тегом. Для верификатора выберите новое пустое назначение. Форматы
данных совместимы, миграция баз и смена ключей для отката не нужны.
